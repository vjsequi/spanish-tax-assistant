# Contributing

Start with AGENTS.md and the current backlog slice. Work on `codex/` branches for agent changes. Link changes to requirement IDs and a decision when the design changes. Keep a vertical slice small enough to demonstrate and inspect.

Run the README commands before marking a slice verified. Use failing behaviour tests before a domain fix and retain the regression. Do not manufacture test breadth by checking that code mirrors itself. Document-only work needs the repository checker; executable changes need lint, types and appropriate tests.

A pull request should explain the problem, resulting behaviour, validation and unresolved limits. New inference, deployment, public data or reviewer claims need actual authorisation/evidence. Never commit real taxpayer inputs or developer credentials. The initial GitHub workflow validates the foundation; it is not a release or model-quality certificate.
