# Product acceptance baseline

**Product baseline 1.0, owner approved 21 October 2026.** These are future verification requirements, not results. There is no tax application, rendered intake, reviewed synthetic dataset, inference result or deployment yet. Existing passing tests and hosted CI cover repository controls only.

## Required first complete outcome

For a fully covered 2025 Balearics individual ordinary annual return, organise supported visual evidence, obtain fact confirmation, independently calculate the complete payable/refundable result, compare a supplied draft, investigate supported deductions and export a Spanish PDF/optional JSON review packet. An AEAT draft is optional at case start. The owner handles official submission and professional sharing.

The [definition](definition.md) and [actual discovery answers](discovery.md) establish the scope. Required branches include ordinary salary/benefits in kind from multiple employers, bank interest, straightforward families with children or no dependants, standard employment expenses, union/mandatory professional fees, individual/employer pension contributions, donations, and independently reviewed rent/childcare branches. Exact legal conditions, field mappings and calculations still need source-derived specification and independent review.

## Blocking release checks

| Gate | Required evidence |
|---|---|
| Complete deterministic calculation | All required reviewed intermediate fields/stages and final balances match their legally prescribed arithmetic/rounding on the declared supported test suite. Totals alone cannot pass when field errors cancel. Derive results from confirmed facts, not supplied draft totals. |
| Coverage and unknowns | Screen material income, household, relief/history and period conditions. Unknown is not zero. Unsupported cases show a partial packet; no whole-return result when completeness is not established. |
| Evidence and review | Each used fact has reviewable source provenance and explicit confirmation; each proposal identifies applicable rule/version and calculation. Conflicts and stale facts cannot pass batch confirmation. |
| Harmful tax output | No harmful/unsupported tax recommendation or unvalidated whole-return claim is shown as a valid proposal or final result. Record rejected unsafe candidates separately; schema validity and source identity do not prove semantic correctness. |
| Security and privacy | No cross-case access, permission expansion through source instructions, private-data exposure or local-reference egress. Verify parsing limits, trusted identity, scoped tools, private storage and redacted diagnostics at their actual boundaries. |
| Recovery and deletion | Demonstrate save/resume, idempotency, stale-worker rejection, bounded uncertain-provider recovery and deletion/backup expiry without resurrecting deleted case content. |
| Review and release evidence | Independently reviewed synthetic expectations and rubric; owner walkthrough; reproducible CI/artifact; actual environment/access/recovery checks before claiming hosted operation. |

Blocking failures do not disappear inside an aggregate quality percentage. A human-approved proposal and independent tax-validation evidence are separate records.

## Pilot targets selected by the owner

| Measure | Target and measurement boundary |
|---|---|
| Workload | About 30 source files and 100 pages per benchmark case, including PDFs, receipts and screenshots. This is a representative test target, not a verified upload limit. |
| Extraction | At least 95% of required readable facts correctly normalised and linked to the right evidence **before confirmation**. A fact passes only when value and evidence are correct. Missing readable facts count as failures; illegible-source cases have a separate reviewed abstention/question rubric. |
| Processing | At least 95% of benchmark attempts produce the required reviewable outputs within five minutes of cumulative automated processing. Include admission/rendering, queue/provider/tool/validation/recovery time; exclude and separately report human pauses. Measure cold activation separately. Failed/timed-out attempts count as target misses. Show progress and allow resume. |
| Human effort | At least 20% less hands-on review time than the comparable manual workflow. Include organising, checking, confirming/correcting facts, reviewing questions/changes and assembling the packet. Record step-level time as well as total time. |

Measure all three value activities: evidence organisation, draft checking and supported deduction discovery. Report missed/incorrect findings, useful questions, correction effort, coverage and safety alongside time. Do not claim statistical generalisation from a small pilot or private reference.

## Comparison and evidence method

1. Establish a manual/checklist baseline on representative supported tasks using normal available tools and the same supplied draft when present. Use the same agreed outcome and documents for comparisons; control order/familiarity effects where possible.
2. Validate the deterministic calculator separately. Compare document representations on the same semantic sources; hold confirmed facts fixed when comparing investigation workflows.
3. Compare rules/checklist, prepared context plus one call and bounded retrieval only after independently reviewed expectations and fresh inference authorisation. Framework/model choice follows observed quality, effort, latency, failure and known-cost trade-offs.
4. Keep inputs separate from scorer/reviewer expectations. Select on development cases, freeze the candidate, then use structurally separate reviewed final cases. Public demonstrations and reused inspected examples are regression evidence.
5. Retain planned/attempted/completed/failed/skipped and pending-review counts, versions, resource limits and unknown cost. Publish synthetic aggregate evidence only. Local private-reference material and private discovery context remain outside Git, cloud and external application providers.
